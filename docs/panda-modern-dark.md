# Panda Modern Dark 配色记录

## 基础与范围

以本机 VS Code 1.140.0 的「2026 深色 / 2026 Dark」为基础，新增 Panda Modern Dark，保留 Panda Vivid Black 与 Glass Dracula。

`themes/base/vscode-2026-dark.json` 是未调色的完整配置副本。依次展开 `dark_vs.json → dark_plus.json → dark_modern.json → 2026-dark.json`：界面颜色与语义规则按键覆盖，TextMate 规则按继承顺序追加。共保留 326 个界面颜色、118 条 TextMate 规则、4 条语义规则，以及原始的语义高亮开关。编辑器在主题文件之外提供的默认值仍由 VS Code 提供。

`themes/panda-modern-dark-color-theme.json` 引用该副本，并覆盖调整后的完整颜色集合。不依赖用户电脑上的 VS Code 安装路径，也不会随内置主题更新自动改变。主题文件没有修改内置主题；本机显示设置的配套调整另记于下文。

## 用户确定的调色原则

参考图不只是要逐项抄色：**必须计算「2026 深色」到参考图的颜色差值，并将这个差值应用到参考图未出现的其他主题颜色中。**

后续澄清：目标是颜色更浓、更鲜明、角色之间更有区分度，不能理解成混入白色、提高所有颜色的亮度。字符串明确选用「2026 深色」JSON 键名的绿色 `#7EE787`，取代此前推算的浅蓝与临时灰绿建议。

参考文件：`HT8kCDJa4AAVL_v.jpeg`，3492 × 2512。JPEG 压缩、字体抗锯齿会改变局部像素；背景与灰阶取稳定区域/笔画中心，彩色笔画取集中出现的代表色。这些是复现用的近似值，不声称还原了截图主题的原始源码色值。

## 对应色与差值

下表的 RGB 差值用于直观核对；其余颜色实际在 OKLab 感知色彩空间中插值，避免所有颜色机械套用一个 RGB 偏移。

| 2026 深色原色 | 参考目标色 | ΔR, ΔG, ΔB |
| --- | --- | --- |
| `#000000` | `#000000` | +0, +0, +0 |
| `#121314` | `#0C0C0C` | -6, -7, -8 |
| `#191A1B` | `#0F0F0F` | -10, -11, -12 |
| `#2A2B2C` | `#272727` | -3, -4, -5 |
| `#8B949E` | `#888888` | -3, -12, -22 |
| `#BBBEBF` | `#E8E8E8` | +45, +42, +41 |
| `#C9D1D9` | `#E8E8E8` | +31, +23, +15 |
| `#FF7B72` | `#FF804F` | +0, +5, -35 |
| `#79C0FF` | `#79B8FF` | +0, -8, +0 |
| `#D2A8FF` | `#B084FF` | -34, -36, +0 |
| `#FFFFFF` | `#FFFFFF` | +0, +0, +0 |
| `#7EE787` | `#7EE787` | +0, +0, +0 |

黑白端点用于约束插值，防止白色文字和透明叠层中的黑白失去原本用途。两种正文灰都映射到参考图的 `#E8E8E8`。

对非对应色 `c`，先把原色、对应原色 `sᵢ`、目标色 `tᵢ` 转到 OKLab：

```
dᵢ² = squared_distance(c, sᵢ)
wᵢ = 1 / max(dᵢ², 1e-15)²
Δ(c) = sum(wᵢ × (tᵢ - sᵢ)) / sum(wᵢ)
result(c) = c + Δ(c)
```

对应色直接使用表中目标值。其他颜色把对应点分成灰阶与彩色两组，分别用上述公式计算差值，距离越近权重越大。用源色的 OKLab 色度 C 区分：C ≤ 0.03 只使用灰阶组；C ≥ 0.06 只使用彩色组；中间线性过渡。这样正文灰白的提亮不会污染蓝、绿、紫等彩色语法。覆盖界面、TextMate 前景/背景以及继承的语义颜色。输出超出 sRGB 色域时，固定色相和亮度、收缩色度至可表示范围。保留原始透明度（短十六进制会展开，但透明度数值不变）。

## 可见角色的直接匹配

图片中的角色颜色优先于推算值：

- 非当前行行号：`#858889 → #3D3D3D`。这是行号专用的低对比度，不把它当成普通灰色的全局对应点。
- 活动标签背景：`#121314 → #0F0F0F`；活动标签文字：`#BFBFBF → #E8E8E8`。
- Dart 关键字、运算符、修饰符、原生类型关键字为橙色，类型名为蓝色，函数名为紫色，普通标识符为灰白。追加实际 Dart 语法作用域，避免继承的 Dark+ 更具体规则覆盖这些颜色。
- 常用语义角色使用同一组颜色，避免语言服务分析后把类、函数或变量换成另一套配色。其他继承语义角色仍按差值计算。
- CodeLens 的 `Run | Debug | Profile` 使用灰白 `#E8E8E8`，取代试用的纯白色。
- Dart 注解整体沿用 `@` 的浅金色 `#FFA618`。同时覆盖 `storage.type.annotation.dart`、`annotation:dart` 与 `*.annotation:dart`，使符号和带 annotation 修饰符的名称保持一致。
- 1.1.1 将属性与 Dart 命名参数标签设为青蓝 `#00D2F9`：语义规则为 `property` 与 `parameter.label:dart`，TextMate 补充 `variable.other.property` 和 `variable.other.object.property`。实际令牌检查确认 `listenable:` 属于带 `label` 修饰符的 `parameter`；不覆盖通用 `parameter`，保留 `context` 等普通参数的灰白色。类名、返回类型和函数名沿用原色。
- 普通字符串与引号明确覆盖为 `#7EE787`，同时覆盖 TextMate 和 `string` / `stringLiteral` 语义角色；转义与插值代码仍保留各自的高亮。JSON 键名保持相同绿色。
- 六级括号统一灰白 `#E8E8E8`，配对引导线用深灰，避免编辑器默认的黄紫彩虹色盖过主题配色。此改动只属于新主题；不修改用户的括号开关或 indent-rainbow 扩展设置。

新主题保留基础规则顺序；追加的 Dart 规则只调整颜色，不增加粗体或斜体。原始 Panda 的字体样式与配色没有带入。

## 实际显示对照后的微调

并排截图的取样显示，主橙色 `#FF804F`、主紫色 `#B084FF` 已接近参考色，蓝色也只有很小的差异。这些采样对应色和字符串绿 `#7EE787` 保持不动。

其余有色部分（OKLab 色度 C ≥ 0.035）在上面的差值映射结果上，将色度提高 25%，固定 L 明度与色相：`(L, a, b) → (L, 1.25a, 1.25b)`。超出 sRGB 色域时仍只收缩色度，不抬高 L；灰阶、透明度和所有采样对应色不变。此步骤同时应用于语法、语义和界面有色部分，避免只调整局部。

典型语法颜色变化：

| 角色 | 前一版本 | 当前版本 |
| --- | --- | --- |
| 数字 | `#B3CCA9` | `#AFCEA2` |
| 转义序列 | `#D2B774` | `#D8B65E` |

本机显示配套调整：保留原字体族、字号和行高，将 `editor.fontWeight` 从默认 400 调到 `500`，让笔画更饱满。它是本机设置，会影响其他主题，不包含在主题扩展内；删除该设置或改回 `"normal"` 即可恢复。主题本身没有增加粗体语法规则。
